# AttendEase — Student Attendance Management System

A beginner-friendly full-stack college project for managing a class roster and recording daily attendance. Built with HTML, CSS, Vanilla JavaScript, Node.js, Express, and Supabase PostgreSQL.

> **Important demo limitation:** This MVP has no login system. It is suitable for local classroom demonstrations only. Do not deploy it publicly as-is: anyone who can reach the server can manage the student roster and attendance. Add verified admin authentication before public deployment.

## 1. Problem and objectives

Paper attendance sheets are easy to misplace and take time to summarize. AttendEase keeps a student list in a database, records present/absent status for a selected date, prevents duplicate roll numbers, and shows a quick summary.

### Target users

- Teacher / class coordinator: add students, search the class list, mark attendance, and review counts.
- Student developer: learn how a browser UI, REST API, and relational database work together.

### Features

- Responsive dashboard with student, present, and absent counts.
- Add students with unique roll numbers.
- Search by student name or roll number.
- Select a date and mark each student present or absent.
- Save attendance in Supabase; re-saving updates the existing student/date record.
- Daily summary includes present, absent, and unmarked counts.
- Delete a student after confirmation; related attendance rows are deleted by a foreign key.
- API validation, safe text rendering, basic security headers, and request rate limiting.

## 5. Setup from an empty folder

### Step 1 — Create the project folders

Create a folder named `student-attendance-management-system`, then create `frontend`, `backend`, `backend/routes`, `backend/utils`, and `database`. Copy the source files into their matching paths.

In VS Code, use **File → Open Folder** to open the root project folder. Open **Terminal → New Terminal**.

### Step 2 — Create the Supabase project

1. Visit https://supabase.com/ and create a project.
2. Save the database password somewhere private; this app does not need that password.
3. Open **Project Settings → API Keys** (the labels may vary by dashboard version).
4. Copy the Project URL and a server-only Secret key (`sb_secret_...`) or the legacy `service_role` key. Do not use a publishable/anon key as the server key.
5. Never paste a secret key into the frontend, a public issue, or GitHub.

### Step 3 — Create the database tables

1. In the Supabase dashboard, open **SQL Editor**.
2. Create a new query.
3. Copy all contents of `database/schema.sql` into the editor.
4. Click **Run**.
5. Open **Table Editor** and confirm `students` and `attendance` exist.
6. Optional: uncomment the demo `INSERT` statement at the bottom of the SQL file and run it to add three sample students.

### Step 4 — Configure environment variables

In the VS Code terminal, from the project root:

**Windows PowerShell**
```powershell
Copy-Item backend/.env.example backend/.env
```

**Command Prompt**
```bat
copy backend\.env.example backend\.env
```

Open `backend/.env` and replace the example values:

```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_SECRET_KEY=YOUR_SERVER_ONLY_SECRET_KEY
```

- `PORT`: local web server port.
- `NODE_ENV`: runtime mode.
- `SUPABASE_URL`: URL from your Supabase project.
- `SUPABASE_SECRET_KEY`: secret/service-role key used only by the server.

The example values do not connect to a real database. Keep `.env` private. The `.env.example` file is safe to commit because it contains placeholders.

### Step 5 — Install packages

From the root directory:

```bash
cd backend
npm install
npm run check
```

`npm install` downloads the packages. `npm run check` checks JavaScript syntax. A successful check exits without syntax errors.

### Step 6 — Start the server

From `backend/`:

```bash
npm start
```

Expected terminal output:

```text
AttendEase server running at http://localhost:3000
```

Open http://localhost:3000 in your browser. Keep the terminal running while using the app. To stop the server, press `Ctrl+C`.

During development, `npm run dev` restarts the server when backend files change (Node 20+).

## 6. How the application works

1. The browser displays `frontend/index.html`, styled by `styles.css`.
2. `frontend/app.js` uses `fetch()` to call `/api/...`.
3. Express validates each request and calls Supabase from the server.
4. Supabase stores students and attendance persistently in PostgreSQL.
5. The browser receives JSON and updates the dashboard.

The Supabase secret is never sent to the browser. RLS is enabled and no public policies are created. The server key bypasses RLS, so server-side validation is essential. Because this MVP has no authentication, keep it local and do not expose it to the internet.

## 7. API reference

All responses use JSON. No authentication is implemented in this classroom MVP; therefore, run it only on a trusted local machine.

| Method | Path | Purpose | Request body / query | Success |
|---|---|---|---|---|
| GET | `/api/health` | Check server/database | None | `{ "status": "ok", "database": "connected" }` |
| GET | `/api/students` | List students | None | `{ "students": [...] }` |
| POST | `/api/students` | Add a student | `{ "name": "Asha Kumar", "rollNumber": "BTECH001" }` | `201`, `{ "student": {...} }` |
| DELETE | `/api/students/:id` | Delete student and attendance history | Positive integer ID in path | `{ "message": "Student deleted.", "id": 1 }` |
| GET | `/api/attendance?date=YYYY-MM-DD` | Read daily attendance | `date` query parameter | `{ "attendance": [...] }` |
| PUT | `/api/attendance/bulk` | Save or update daily attendance | `{ "date":"2026-10-28", "records":[{"studentId":1,"status":"present"}] }` | `{ "message": "Attendance saved.", "attendance": [...] }` |

Common errors: `400` invalid input, `404` unknown endpoint/student, `409` duplicate roll number, `500` operation failed, `503` database unavailable/not configured.

## 8. Sample usage

1. Open the dashboard.
2. Add a student name and unique roll number.
3. Repeat for the class roster.
4. Choose the attendance date.
5. Select Present or Absent for every student.
6. Click **Save attendance**.
7. Change the date to see that date's saved attendance.
8. Search using a name or roll number.
9. Use the delete icon and confirm to remove a student.

If you used demo SQL data, those rows are sample records. Replace them with your class list in the UI.

## 9. Testing checklist

- [ ] Visit `/api/health`; expect database `connected` when credentials and schema are correct.
- [ ] Add a valid student; expect it to appear in the table and remain after refresh.
- [ ] Add the same roll number again; expect a friendly duplicate message.
- [ ] Search by name and roll number; expect only matching rows.
- [ ] Save attendance for every student; expect a success message and updated summary.
- [ ] Change date and return; saved records should reappear for their dates.
- [ ] Try saving with a student unmarked; expect a validation message.
- [ ] Submit blank name/roll number; expect an error.
- [ ] Try an invalid date through the API; expect `400`.
- [ ] Delete a student; expect their roster row and attendance history to disappear.
- [ ] Resize the browser to phone width; controls should wrap and table can scroll horizontally.
- [ ] Stop the server and reload; the UI should show a connection error.
- [ ] Temporarily use invalid Supabase credentials; health check should show unavailable.

Syntax check:
```bash
cd backend
npm run check
```

This checks JavaScript syntax only; it does not verify a live Supabase project or browser behavior.

## 10. Troubleshooting

- **`node` or `npm` not recognized:** install Node.js LTS, then close and reopen VS Code.
- **Port 3000 already in use:** change `PORT=3001` in `backend/.env`, restart, and open `http://localhost:3001`.
- **Database not configured:** confirm `backend/.env` exists and has no placeholder values; restart server after editing.
- **Database unavailable:** verify project URL/key, internet connection, SQL schema, and table names.
- **Duplicate roll number:** each roll number must be unique.
- **Table not found:** run `database/schema.sql` in the correct Supabase project.
- **Changes not visible:** reload the browser; make sure the terminal server is still running.
- **`npm install` errors:** verify Node 20+, internet access, and that the terminal is in `backend/`.

## 11. Security and limitations

- This MVP deliberately does not include accounts, login, roles, or per-teacher data isolation.
- Do not deploy it to a public host as-is. Add Supabase Auth or a server-managed session and enforce verified admin authorization before public use.
- The server-only key bypasses RLS; never expose it to the browser or commit it.
- Keep Node dependencies updated and rotate any key accidentally exposed.
- The API has basic rate limiting and security headers, but it is not a complete production security setup.
